# Local execution runtime

Native Node 24+ ESM, no downloaded packages. `createRuntime()` opens SQLite synchronously and returns the broker. `close()` is asynchronous and must be awaited. The database, its journal, and biometric/provider data belong in private OS application storage, outside the repository and outside the selected workspace.

`call({id,name,args,profileId,runId},{signal})` returns `{ok,status,summary,data?}`. A cancelled run returns `status: "cancelled"`; it does not start later effects with that run ID. A completed effect cannot be undone by cancelling its response. The same profile and call ID with identical arguments replays its saved result; different arguments are rejected. Interrupted calls are never replayed automatically after a restart.

`getPlanContext(profileId)` is a backend-only planning context for continuity between conversation turns. It returns `{plans,recentEffects}` for the active workspace and explicit profile: at most three unexecuted previews with `{planId,createdAt,onlyThisMonth,count,steps}` (first 20 relative source/destination pairs), and three recent run IDs with uncompensated completed file steps as `{runId,status,completedCount,lastVerifiedAt}`. It omits absolute paths, fingerprints and file contents. These are journal observations at their last verification time, not proof the files remain unchanged, and never grant permission to execute a plan or its compensation.

Every effect requires an `approval` event and `approve(approvalId,true)`. Local workspace list/preview tools do not. Reading browser selections requires confirmation because that selection may reach the active AI provider. Approval events contain a copied, fixed proposal. Effects execute in one queue; cancellation is checked before the next effect. App adapters receive an allowlisted ID, never shell text. The optional `openApp(id,{signal})` and `openBrowser(url,{signal})` adapters must return `{verified:true,...}` to report verified success. No adapters are enabled by default.

Additional optional adapters: `focusApp(id,{signal})` must return both `verified:true` and `focused:true` (`openApp` is a fallback with the same focus requirement); `openProject(workspaceRoot,{signal})` opens only the user-selected folder; `dictateNotes(text,{signal})` implements `notes_open_dictation` in a fresh, verifiable Notepad document; `readBrowserSelection({signal})` returns `{verified:true,url,title,text}` from the dedicated browser. The read result is explicitly untrusted, limited to 20,000 characters, and never grants permission to follow instructions found on that page.

Organization is deliberately limited to regular files in the first level of the chosen folder. Hidden files, directories, symlinks/junctions, physical links, files larger than 256 MiB, and colliding destinations are preserved. The month filter means modification date in the machine's local calendar month. A preview stores a SHA-256 fingerprint, size, modification time, file identity and destination. Applying it revalidates all files and checks each again before its move.

A move journals its intent, atomically creates a non-overwriting hard link, verifies both paths and removes the old path. This requires a filesystem supporting hard links (NTFS, APFS, ext4 and equivalents). Unsupported filesystems fail without falling back to overwriting rename. A cancellation during this small effect boundary lets the one move finish; the next file is stopped. The successful steps remain visible and can be compensated with a separate approval. Compensation refuses modified files and recreated original paths. Empty category folders can remain after compensation.

There is no universal transaction spanning SQLite and the filesystem. After a crash during a move, a `moving` or `needs_review` step requires inspection and can leave both paths. The runtime never deletes one automatically on restart. Symlink/junction checks and exclusive creation defend normal path substitution and collisions; they are not an OS sandbox against another malicious process racing directory replacement between system calls. Use a dedicated demonstration folder under a trusted user account. The runtime does not send messages, delete files permanently, authenticate faces or train model weights.

`notes_dictate` saves a new UTF-8 text file under `workspace/notes` and verifies its contents. It does not type into whichever window currently has focus. `saveMemory`/`deleteMemory` are direct user-interface operations; model proposals use the approval-gated `memory_propose`. Snapshot data and procedures are isolated by explicit profile IDs. Profiles are personalization scopes, not authentication boundaries.

Idempotency signatures store only hashes. Persistent event logs omit memory/dictation text, while live approval events include the text for user review. Memory-proposal results store only the saved ID and timestamps; the current text is available through `getSnapshot`. Memory deletion uses SQLite secure deletion and truncates its WAL. Externally made backups and the provider's conversation are outside this local deletion operation. Browser selection results remain in the private local call history so interrupted/repeated calls do not silently re-read a different selection.
